# Text CAD rework design references

Inspected on 28 October 2026. These references informed interaction and layout; their documentation-site navigation was not copied as an application UI.

- A CADAM fork was inspected as the implementation reference; [upstream CADAM](https://github.com/Adam-CAD/CADAM) is linked here to avoid publishing a personal fork identity. README.md, src/components/Layout.tsx, src/components/Sidebar.tsx, src/components/chat/ChatSession.tsx and the editor route were retrieved from the inspected fork. Layout persists a collapsible sidebar; Sidebar groups recent conversations; ChatSession has conversation-scoped streamed state and persisted tool output. These are architectural/interaction references; no source was copied.
- [CADAM application preview](https://adam.new/opensource), specifically the linked application screenshot, rather than the surrounding marketing page. Observed: quiet dark surfaces, a dominant model view, compact artifact/version cards and contextual parameter controls. Our right-side conversation and left CAD manager follow the requested arrangement while retaining our own branding.
- [Zoo Zookeeper](https://zoo.dev/docs/zoo-design-studio/zookeeper), including its actual application screenshot. Observed: compact application/command bars, a thin navigation rail, a prominent viewport and a right conversation/composer. We adopted the hierarchy and restraint, with only working native commands.
- [Adam projects guide](https://docs.adam.new/guides/projects): project-level grouping of related tasks and shared context informed the separation of project navigation from CAD structure. Our storage remains local and document revisions remain independent of chat selection.

The implementation uses original monochrome vector rail icons, restrained teal accents, readable selection properties, compact command groups and collapsible activity details. At laptop widths, secondary panes collapse before the viewport becomes too narrow. UI checks generate screenshots and measured viewport sizes in the ignored local artifacts directory; these are not published in Git.

The settings bug was reproduced in the original running application: three additional rail clicks produced three additional modeless dialogs. Inspection found one rail handler connected once, and an unconditional new QDialog on each activation. The replacement uses one owner-bound QPointer; activation raises the existing dialog, and deletion on close clears the pointer. Save snapshots the staged preferences, disables duplicate requests and uses lifetime-safe completion callbacks. Cancel discards staged preferences. Connection buttons are explicitly immediate actions.
