# Current workspace architecture

```text
C++ / Qt CAD workspace
    │ private JSON-RPC process channel
backend.v2.service / WorkspaceV2
    ├── Projects, documents, conversations, tasks and revisions
    ├── Protected ChatGPT / API-key connections
    └── Codex App Server adapter
            │ nine scoped CAD MCP tools
            └── Candidate geometry operations
                    │ private geometry worker
                    └── backend.native
                        CadQuery / OpenCascade solids, recipes and meshes
```

The shared CAD core contains geometry, recipe/schema validation, parameter arithmetic, topology inspection and document storage. It contains no separate HTTP application, custom model provider or legacy chat implementation. The current agent layer owns authentication, App Server streaming/cancellation, task correlation, project/chat persistence, restricted CAD scripts and candidate acceptance.

The agentic-capabilities source adds trusted component transactions, content-addressed editable definitions, independent geometry/appearance/engineering change checks and project-relative image attachments. Ownership records are generated by application code and checked against frozen scope. Model modality declarations and provider bounds are cached independently of account access; unknown image support blocks image submission. See [the capability contracts and pending validation](agentic-cad.md). The local native executable has been rebuilt; tests, live inference and UI verification remain pending.

Tasks freeze revision and explicit selection context. Tools reject stale references and changes outside submitted component scope. Project-root lifecycle locks, per-document locks and revision comparison serialize geometry writes. Independent validation precedes acceptance; failed/cancelled candidates preserve the accepted revision. Multiple conversations read the actual current document state.

Credentials are protected with Windows DPAPI. The native application owns its backend process tree, the provider owns App Server/tool descendants, and geometry runs in a controlled worker. Internal viewport captures are observations; image generation is not an active workflow. Ordinary modelling uses CAD tools and never modifies application source.

The interface uses one shared dark/light theme for controls and the CAD background. The startup splash owns the logo and an indeterminate animation until the local document service is ready. The native chat renderer uses rounded user bubbles and unboxed assistant replies with selectable Markdown text. One Send control becomes Stop during a task and disables during cancellation. Observable work events expand inline, and completion duration/activity persist on the response. It coalesces streamed text updates and never displays reasoning events. Submitted prompts are removed immediately; later drafts survive task completion. Documented App Server commentary phases are saved as activity, while partial and final answers remain visible. Legacy messages without phase metadata retain their text.

New project collections use named, ignored Projects/ folders and relative document paths. Imported project folders preserve conversation history and start a fresh provider session if the previous runtime is elsewhere. Account credentials are stored separately with Windows protection. Installer inventories are explicit and exclude project and runtime data even when these sit beside the application.

Usage observations are provider-specific: reported allowance windows become remaining percentages with the reported duration/reset, while thread token counts remain separate. The app-owned API-token route can lack allowance reporting; the workspace hides an unreported allowance and uses actual reported token counts when available. Billing management stays in account settings.

## Account and project lifecycle

Normal startup keeps the document and conversation empty. First-run setup is skippable and uses the same app-owned authorization flow as Settings. The preferred ChatGPT registration is retained after disconnect; client IDs and host IDs are reused, while legacy credentials remain separate. Authorization completion, cancellation and expiry emit local connection state. Model discovery is serialized and cached for ten minutes per account; an explicit refresh bypasses a completed cache entry.

Project folders are authoritative. `v2.projects.refresh` rebuilds the catalogue from valid folders and clears missing active context. `v2.project.purge` accepts a project ID; `v2.conversation.purge` also requires a conversation ID. Both require the target to be in trash and reject concurrent writes. Project deletion validates containment and refuses filesystem links; chat deletion retains shared document geometry and revisions. A project can retain documents with no active conversation.

## Workspace selection and copying

Selection version 2 carries a revision-bound entity array across components. Legacy single selections normalize into the same representation. The tool boundary enriches every selected entity with geometry identity and coordinate context, constrains face/edge/region command targets, and checks unselected component fingerprints. Changed sub-entity references become stale when no verified mapping exists. `cad_apply_batch` resolves all planar face-offset/hole tools before applying them to candidate solids; failed/cancelled batches do not replace the accepted document. `v2.command_batch` exposes the same validated path to contextual CAD controls.

`v2.project.save` checkpoints accepted metadata without adding a geometry revision. `v2.project.save_as` stages an independent project copy, remaps project/document/conversation/task/revision IDs and structured links (including retained branch revisions), verifies geometry/reference assets, clears provider-session bindings, and publishes a new named project folder. `v2.conversations.batch` accepts stable project/chat pairs and archive, trash, restore, unarchive or purge; results are reported per item. Archive and Trash have separate filtered views. Restore only clears trash; unarchive clears archive, making repeated actions idempotent.

The native composer handles Enter/Shift+Enter and IME composition. Model choice and reported usage use themed popovers; account details are separate from Settings. Application notices render outside conversation history. User scroll actions carry a generation so delayed message-layout callbacks cannot override a newer reading position.

`provider.login` accepts an explicit `new_registration` flag; normal reconnect continues to reuse the primary registration. Cross-window authorization uses an OS-held lease. `provider.forget` removes only an old local registration after attempted session revocation and refuses the active/preferred registration. Removing a local record does not remove a registered app from ChatGPT.
